💡 1. Introduction & Motivation

Shield Labs • Slide 2 / 12
🌐 The Endpoint Security Landscape
  • Modern enterprise and campus environments operate across dynamic multi-laptop fleets over shared Wi-Fi subnets.
  • Endpoint workstations are primary vectors for lateral malware movement, ransomware, and unauthorized network snooping.
  • Legacy administration platforms suffer from fragmented architecture, requiring split servers and unencrypted background daemons.
🎯 Our Core Motivation
  • Single-Port Defense: Consolidate monitoring, fleet telemetry, and remediation into one web console (`0.0.0.0:3000`).
  • Zero Invasive Surveillance: Guarantee complete endpoint security with ZERO keylogging, ZERO screen recording, and full user transparency.
  • Zero-Trust Isolation: Protect analyst privacy by preventing secondary users from inspecting other devices.
Speaker Script: "In modern IT environments, endpoints are the most vulnerable entry point. However, current tools either act as intrusive spyware or leave unauthenticated backdoors open. Our motivation was to deliver robust endpoint visibility and remediation while strictly preserving user privacy."

⚠️ 2. Problem Statement & Existing Flaws

Shield Labs • Slide 3 / 12
🚨 Header Spoofing (LAN)

Traditional servers blindly trust client-supplied headers like X-Forwarded-For.

  • LAN attackers forge 127.0.0.1 to bypass admin gates.
  • Unauthenticated callers gain unauthorized elevated roles.
🔓 Public Token Leaks

Commercial fleet managers broadcast bearer tokens over open HTTP enrollment routes.

  • Wildcard CORS exposes session credentials.
  • Unverified agents execute destructive remote commands.
👁️ Covert Surveillance

Existing monitoring software intercepts private user activity without consent.

  • Secret keystroke logging & screen capture violate ethics.
  • No transparency badge on monitored student/worker laptops.
Speaker Script: "During our security audit, we identified three critical flaws in conventional endpoint monitors: Header-based identity spoofing, plaintext token leaks on enrollment routes, and invasive, unconsented surveillance. Shield Labs eliminates all three vulnerabilities."

🛡️ 3. Proposed Solution & Objectives

Shield Labs • Slide 4 / 12
⚙️ Architectural Objectives
  • Single-Port Unified Service: Run frontend, API, WebSocket, and telemetry strictly on Port 3000.
  • One-Click Fleet Enrollment: Support both agentless TCP socket auditing and lightweight PowerShell telemetry scripts.
  • Heartbeat Deduplication: Preserve node persistence across browser reloads without spawning duplicate devices.
🔒 Cryptographic & Privacy Objectives
  • PBKDF2 SHA-256 Vault: 100,000 iterations with 16-byte random salts and timing-safe equality comparisons.
  • Dual-Mode Email OTP: Cryptographic 6-digit numeric verification with anti-flood cooldowns.
  • Role Immutability: Public signup defaults to SECURITY_ANALYST; only Master Admin can delegate roles.
Speaker Script: "Our proposed solution focuses on two core pillars: Architectural unification onto port 3000, and cryptographic zero-trust validation. Every user signup is verified via email OTP and restricted to analyst clearance, while the host hardware is hidden from secondary users."

🔄 6. Working Principle & Execution Flow

Shield Labs • Slide 7 / 12
🔁 Continuous 4-Phase Security Loop
1. Ingestion

Endpoints stream CPU, RAM, & download scans every 5 seconds.

2. Validation

Raw socket IP normalized; spoofed headers discarded.

3. RBAC Gate

Role immutability enforced; sessions default to locked NO_ROLE.

4. Remediation

Master Admin dispatches process kills & quarantines.

🛡️ Zero-Trust Device Privacy Isolation

When a student or analyst logs in on Laptop 2, the API automatically masks Host Laptop 1's hardware, CPU vitals, and storage. The analyst only ever sees their own laptop.

Speaker Script: "Our execution flow operates in a continuous 4-phase loop. Every 5 seconds, telemetry is ingested, sanitized through socket validation, filtered through RBAC, and presented to the admin. Critically, device privacy isolation ensures analysts never see host diagnostics."

🔒 7. Zero-Trust Security & Anti-Takeover Hardening

Shield Labs • Slide 8 / 12
🛡️ Anti-Takeover OTP Architecture
  • Decoupled Verification: POST /auth/otp/verify strictly marks user.isVerified = true. It never elevates or issues an authenticated session.
  • Zero Credential Bypass: Admin accounts can never be taken over with OTP alone; full login requires Master Password or PIN.
  • Anti-Flood Cooldown: 30-second resend cooldown and rate-limiting prevent brute-force attacks.
🛡️ Header Spoofing & Token Isolation
  • Header Discard: X-Forwarded-For and X-Real-IP headers are completely discarded; client identity is derived strictly from TCP socket.
  • Token Redaction: /api/v1/enrollment redacts the global IPC token unless caller is already authenticated as ADMIN.
  • Restricted CORS: Permits only legitimate local loopback and host interface origins.
Speaker Script: "A key technical achievement was resolving the zero-credential OTP takeover vulnerability. We completely decoupled email verification from session issuance. Now, verifying an OTP never silently elevates a caller to admin without verified password credentials."
